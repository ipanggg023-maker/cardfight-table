# Play Flow (online only, table v6, readable battles) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every match is online (no one-screen play, no Judge panel). The game table is drawn without playmat pictures, in the user's sketch layout with a G zone. Every battle moment is paced and shown clearly, in step on both screens.

**Architecture:** The engine's existing `beat(kind)` pause grows into named moments (draw, call, attack, guard total, check show / trigger / move…). The engine also exposes display-only state: `S.checking.stage`, `S.resolving`. `js/pace.js` maps each moment to a wait. The screen's `FX` module in ui.js plays one animation per moment. The table layout keeps today's mechanism (`MAT_LAYOUT` percentages, opponent half rotated 180°) with new numbers and CSS circles. No rules change.

**Tech Stack:** Plain browser JS (no build), Node 24 `node:test` for engine tests, the built-in browser pane (`preview_start {name:"vanguard"}` = `node tools/serve.mjs 8080`) for screen checks.

**Spec:** `docs/superpowers/specs/2026-11-19-play-flow-design.md`, mockup `docs/superpowers/mockups/table-v6.html`

## Global Constraints

- No rule changes, no card-system changes; restructure files only where a task says so.
- No new image assets. Circle rings: `assets/mat/rc.png` (rear-guard, yellow), `assets/mat/vc.png` (vanguard, blue), `assets/mat/gc.png` (guardian circle, green).
- Original look: no official logos, card-game art, characters or catchphrases. In-game text in English.
- Animate only `transform` / `opacity`; never wait on `requestAnimationFrame` alone (pair it with a timer); patch the DOM, don't rebuild (CLAUDE.md "60 fps rules").
- `prefers-reduced-motion`: no zoom or movement, about half the waits, same order.
- Hidden information never reaches the other screen: the opponent's hand, draws and face-down cards.
- No Judge panel anywhere. Card steps the game can't do (effect `manual`) are done on the table (`renderDoing`).
- No "are you sure?" dialogs for ordinary steps (end phase, take the attack).
- Commits: `git -c user.email=334285765+ipanggg023-maker@users.noreply.github.com commit`, message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never commit Bushiroad card text, lists or art.
- Each task updates the CLAUDE.md lines it makes wrong (sections named in the task).

## Review Focus

1. **A click during a pause** (the player presses Attack while a check card is still zoomed) must not act on a moment they haven't seen: the engine refuses it (`S.busy`), and the screen shows no error toast for it. → Task 1 test `refuses actions while a beat waits`; Task 2 step that silences that message.
2. **The opponent's draw online**: the guest must see only a card back flying to the host's plate, never the card. → Task 8 test `snapshot hides drawn cards` + browser check.
3. **A background tab**: a host whose tab is hidden must not stall the match. → Task 2 test `hidden tab waits 60 ms`.
4. **Small screens** (1280×720, 1366×768): no zone overlaps another, and the card detail panel never covers the opponent's zones. → Task 5 browser check at both sizes.
5. **A full damage zone** (6 cards, some Counter-Blasted face down): all six visible, stacked, face-down ones show the card back. → Task 5 browser check with `testOp` damage fill.
