# Bot Opponent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A computer opponent (Easy / Normal) that plays a full game in the browser against the player, for practice and deck testing.

**Architecture:** `js/bot.js` (global `Bot`, also `module.exports` for Node) decides one move at a time by scoring the legal moves, and makes it through the same `Game.*` calls the screen uses. Hidden information comes only from `Game.snapshot(seat)`. Public helpers (`Game.power`, `Game.canAttack`, `Game.boosterFor`, `Game.attackPower`, `Game.defensePower`, `Game.actList`, `Game.driveOf`) may be used. ui.js runs the bot in a local game `index.html?bot=easy|normal` (seat 1), with a think time before each move. No rules change.

**Tech Stack:** Plain browser JS, Node 24 `node:test` (`tools/tests/load.cjs` loads the engine; it gains `js/bot.js`), browser pane (`preview_start {name:"vanguard"}`) for the screen.

**Spec:** `docs/superpowers/specs/2026-11-19-bot-design.md`

## Global Constraints

- No rule changes. The bot acts only through public `Game.*` actions and `Game.answer(ids)`.
- Fair: hands, deck order and face-down cards are read only from `Game.snapshot(botSeat)`, never from `Game.state()`.
- Never stuck: after 3 refused moves (`{ok:false}`) in one decision, the bot takes the safe fallback (manual step → "skip"; yes/no → "no"; other choice → the first `min` options; ride → `skipRide`; stride → `skipStride`; main → `toBattle`; battle → `endTurn`; guard → `confirmGuard`) and logs `🤖 fallback: <what>`.
- Think time 600 ms before each bot move (`Bot.THINK_MS = 600`); none in Node tests; no extra wait in a hidden tab.
- Bot games give no coins (`reportMatch` is not called).
- In-game text English. Commits: `git -c user.email=334285765+ipanggg023-maker@users.noreply.github.com commit`, message ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; push after the work is merged (user-approved).
- 60 fps rules from CLAUDE.md for any screen change.

## Review Focus

1. **A bot deck with hand-done (manual) card steps**: the bot must skip them and keep playing, not freeze waiting for "Done". → Task 1 test `manual step is skipped`.
2. **A pending choice with no good option** (an ability asks the bot to choose 2 cards from an empty-ish zone, or every option is refused): the game goes on. → Task 1 test `refused moves fall back`.
3. **The player clicks during the bot's think time**: the player's click must not be swallowed or crash; actions that aren't the player's turn are refused as today. → Task 4 browser check.
4. **Game over in the middle of a bot move** (the bot's attack deals the 6th damage): the bot loop stops; no errors after the win screen. → Task 1 test `stops at game over` (the 20-game run asserts no step after `winner !== null`).
5. **Formats**: a Premium deck (no ride deck, G deck) against the bot must also play to the end (stride / G guard choices). → Task 1 test runs 5 of its games with `format: "premium"` decks that have a G deck.

### Task 2: Normal level rules

**Files:**
- Modify: `js/bot.js` (the decision functions)
- Test: `tools/tests/bot.test.cjs`

**Interfaces:**
- Consumes: Task 1's `Bot.decide` / `Move`.
- Produces (internal, exported for tests as `Bot._`): `guardPlan(view, seat, level) → Move[]`, `attackPlan(view, seat, level) → Move[]`, `callPlan(view, seat, level) → Move[]`, `mulliganPick(view, seat, level) → number[]` (uids to return), `discardPick(cards) → uid` (least useful: extra grade 3 first, then grade 0 non-trigger, never a sentinel when another card works).
- Rules (from the spec, exact numbers):
  - Guard: shortfall = `attackPower − defensePower`; shield needed = `shortfall + 1`, plus `5000` when the attacker is the vanguard (normal level). Damage 0–2: guard rear-guard attacks never; the vanguard only if one card covers it. Damage 3: guard the vanguard; rear-guards only if one card covers it. Damage 4–5: guard everything that would hit with the fewest shield points that cover it; at 5 damage, if hand shields can't cover it, guard with a sentinel. Intercept: at 3+ damage, use a grade 2 front rear-guard (not the attacked unit) before hand cards whenever it counts toward the shield needed.
  - Attack order: rear-guards that can hit the vanguard (attack power ≥ defender power) first, vanguard last; vanguard first when the opponent has 5 damage. Boost whenever `Game.boosterFor` gives a booster. Target: the vanguard, unless the rear-guard can't reach the vanguard's power but can hit a rear-guard with power ≥ 10000.
  - Calls: fill empty front rear-guard circles with the highest-power units, then back circles behind front units with grade 0–1 boosters; replace a rear-guard only when the new card's power is ≥ 5000 higher. From 3 damage keep at least 2 shield cards (shield > 0) or 1 sentinel in hand.
  - ACT / orders: use when payable and the ability's Counter-Blast doesn't take the last face-up damage that a vanguard ACT needs. Yes/no "use ability?": yes unless its cost would discard the last card in hand.
  - Trigger power: to the next attacker still to come this battle phase; when the vanguard is the attacker or nothing is left, to the vanguard. Critical: to the vanguard. Heal and any other card choice: the first option.
  - Mulligan (Standard with ride deck): return grade 3+ hand cards beyond one, and grade 2 beyond two; Premium: return grade 3+ beyond one.
  - Ride: ride deck first; discard by `discardPick`.

  - `fills the front row with the strongest`: hand [8000 G1, 10000 G2, 12000 G2], empty RCs, bot vanguard G2 → first two calls go to front circles with the 12000 and 10000.
